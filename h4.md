## X) Karvinen 2023: Configuration Management of Distributed Systems over Unreliable and Hostile Networks

## 4.12.1 Size and Complexity of Some DSLs (112. Ominaisuuksien määrä.)

- Konfiguraationhallinnan kieli DSL voi kasvaa suureksi ja monimutkaiseksi
- Saltissa ohjausrakenteet tehdään Jinja2-malleilla, jotka tuottavat YAML-koodia. Se lisää ylläpitäjälle yhden abstraktiotason.
- Puppetissa on noin 113 funktiota. Niitten ohjausrakenteet poikkeaa tavallisesta ohjelmointikielistä. Esimerkiksi jos on toistuvia tehtäviä ne tehdään Puppetin omalla käsitteellä eikä funktiona.

## 4.12.2 Use of DSL Functions in Case Configuration (112-115. Mitä oikeasti käytetään.)

- Mozillalla käytetyimmät olivat case 20%, file 19%, package 10%, exec 6%, service 3% ja yli prosenttin saaneet komennot kattoivat yli 87% kaikesta käytöstä.
- USGCB:ssä käytettyimät olivat augeas 22,5% ja file, service, exec ja package.

## 4.12.3.1 Dependencies Between Main Functions (115-117. Tärkeimmät rakennuspalikat.)

- Järjestelmän pitää olla idempotentti, joka tarkoittaa muutos tehdään vain, jos järjestelmä ei ole jo oikeassa tilassa.
- Oikein konfiguroitu ja säännöllisesti ajettava järjestelmä ei tee tavallisia ajoilla muutoksia.
- Useimmat funktiot ajavat koneen omaa funktiota. Esim package ajaa debianissa apt-get komentoa.

Tarkistin ensin lähtötilanteen ja varmistin ettei PosgreSQL ei ollut asennettuna.

Valitsin demoniksi PostgreSQL-tietokantapalvelimen. Tein asennuksen Karvisen package-file-service-mallin mukaan.

Tarkistin ensin lähtötilanteen komennoilla `sudo ss -tlnp` ja `psql --version`. Portissa 5432 ei kuunnellut mitään, ja `psql` antoi `command not found`, joten PostgreSQL ei ollut asennettuna.

![Lähtötilanne](URL)

Päivitin pakettiluettelon komennolla `sudo apt-get update` ja asensin PostgreSQL:n komennolla `sudo apt-get -y install postgresql`.

![Asennus](URL)

Tarkistin demonin tilan komennolla `sudo systemctl status postgresql`. Komento `pg_lsclusters` näytti tietokantaklusterin version 17, portin 5432 ja tilan [online].

![Demonin tila ja pg_lsclusters](URL)

Testasin tietokantapalvelimen komennolla `sudo -u postgres psql -c "SELECT version();"`. Komento ajettiin tietokannan pääkäyttäjänä postgres, ja tulosteessa näkyi PostgreSQL:n versio. Palvelin siis vastasi kyselyihin.

![SELECT version](URL)

Loin itselleni tietokantakäyttäjän komennolla `sudo -u postgres createuser elmi`. Kun yritin luoda tietokannan, komento antoi virheen `invalid option -- '0'`, koska olin kirjoittanut valitsimen `-O` sijaan nollan `-0`. Korjasin komennon muotoon `sudo -u postgres createdb -O elmi elmidb`.

![createdb-virhe](URL)

[Jos teit taulun: Kirjauduin tietokantaan tavallisena käyttäjänä komennolla `psql elmidb`, loin taulun pizzat, lisäsin siihen rivin ja hain sen `SELECT`-kyselyllä.]

Tein PostgreSQL:lle oman asetustiedoston komennolla `sudoedit /etc/postgresql/17/main/conf.d/elmi.conf`. Debianissa PostgreSQL lukee lisäasetukset conf.d-hakemistosta, joten pääasetustiedostoa ei tarvinnut muokata. Lisäsin tiedostoon rivin `work_mem = '16MB'`. Tarkistin tiedoston sisällön komennolla `sudo cat /etc/postgresql/17/main/conf.d/elmi.conf`.
